# 抖屏助手（dyshuaping）

一个**仅限本人自用、临时调试**的 Android 无障碍工具：在用户手动开启后，通过 AccessibilityService 操作抖音直播间评论框，按随机节奏循环执行「直填或定位输入框 → 输入文字 → 点发送 → 立即进入下一轮」的流程。可随时暂停、继续或停止。

- Debug APK，包名 `com.mqx.dyshuaping`，版本 `1.4.0`
- 默认目标应用：`com.ss.android.ugc.aweme`（抖音）
- 无 Hook、无 root、无 Xposed、无 Shizuku、无改包名、无模拟器伪装
- 只读取和操作设置中目标包名的窗口，其他 App 一律不触碰

> ⚠️ 免责声明见文末。频繁刷屏可能违反平台规则，导致限流或封号，请自行评估并承担风险。

## 1. 能做什么

- 多条评论内容（一行一条），随机抽取或顺序循环发送
- 每条评论末尾自动追加 1~3 个防重复后缀（符号 / 数字 / 抖音表情代码，可多选）
- 最近 20 条已用的完整后缀尽量不重复（`ArrayDeque` 记录）
- 发送间隔 0.0~60.0 秒可调（默认 0.0~0.0 秒，步进 0.1），允许真正零间隔；抖动可关，关闭时不加任何额外延迟
- 打开抖动后，实际间隔 = 区间随机值 + 0~抖动上限随机值（上限默认 0.5 秒）
- 发送前优先在无障碍树里找 `isEditable` 节点直填：先 `ACTION_SET_TEXT`，被拒才 `ACTION_FOCUS` 后重试；成功则不点输入框、不弹键盘，失败自动回退旧点击路径
- 自动轮次点击发送后零等待，下一轮定位兼作上一轮校验；找不到输入/可编辑节点时 20ms 轮询、2000ms 超时才判失败
- 点击坐标 ±3px、按压 25~40ms 随机
- 悬浮窗：开始 / 暂停 / 停止 / 试一轮 / 补发一次 / 抓节点 / 坐标校准 / 隐藏
- 悬浮窗「补发一次」：仅在已暂停或已停止状态执行一次完整单发，用于**测试自己是否被禁言**；不追加随机后缀，不恢复主循环；结果醒目显示 5 秒；长按按钮可直接修改补发内容
- 通知栏常驻前台服务：暂停 / 继续 / 停止
- 全透明沉浸校准页：没有任何常驻面板/准星/按钮，Toast 提示；第一下点评论输入框，第二下点发送按钮，每一下都通过 `dispatchGesture` 回放到下方抖音；满两点自动保存；双击撤销，返回取消；无障碍未开时只记录不回放；节点定位失败时坐标兜底
- 单步调试日志（最近 200 条），一键复制 / 分享
- 当前窗口节点树抓取，写入 `/sdcard/Download/dyshuaping_nodes.txt` 并弹出分享
- 切出抖音自动暂停，切回抖音自动继续；连续失败 3 次自动暂停

## 2. 构建

环境要求：JDK 17、Android SDK（compileSdk 34 / build-tools 34.0.0）。

```bash
cd /home/mqx/projects/dyshuaping
./gradlew assembleDebug
# 或
./build.sh
```

构建产物：

```text
app/build/outputs/apk/debug/app-debug.apk
dist/app-debug.apk   # build.sh 会复制一份
```

项目已配置国内 Maven 镜像（阿里云）和腾讯 Gradle 分发镜像。若本机没有 `JAVA_HOME` / SDK 环境，`build.sh` 会尝试使用本机已验证的 `~/toolchains/dyshuaping/jdk` 和 `~/android-sdk`。

## 3. 安装

```bash
# 方式一：adb
adb install -r app/build/outputs/apk/debug/app-debug.apk
# 或
./install.sh

# 方式二：把 APK 传到手机，点击安装
```

首次安装需允许“安装未知应用”。

## 4. 开启三项权限

打开 App，按“运行权限”卡片的顺序操作：

1. **悬浮窗权限**：点击“去授权”，在系统设置允许“显示在其他应用上层”。
2. **通知权限**：Android 13+ 会弹系统通知授权；如果之前拒绝过，点击卡片按钮进入系统通知设置手动打开。
3. **无障碍服务**：点击“去开启”，在系统无障碍列表中找到「抖屏助手 · 自动评论」并开启。

## 5. Android 13+ 与 ColorOS 的“受限设置”

在 ColorOS / realme UI / OxygenOS 等系统上，侧载 APK 后无障碍开关可能是灰的：

**应用信息 → 右上角 ⋮ → 允许受限设置**，然后再打开无障碍服务。

小米 / vivo 等系统建议同时允许“后台弹出界面”、自启动、后台运行，避免悬浮窗或前台服务被回收。

## 6. 坐标校准

1. 先在抖音进入一个直播间，确认评论框和发送按钮可见。
2. 打开校准页：
   - 在抖音直播间内展开悬浮窗，点「校准坐标」；或
   - 先在抖音直播间，再回到抖屏助手主页点「开始校准」。主页任务会退到后台，校准页覆盖在刚才的直播间之上。
3. 校准页**完全透明**：没有遮罩、准星、说明条、微调按钮或测试按钮，只有纯 Toast 提示；状态栏和导航栏隐藏，页面铺满真实屏幕。
4. 第一下直接点评论输入框。透明层会记下这个点，并临时设置 `FLAG_NOT_TOUCHABLE`，再用 `dispatchGesture` 在**同一坐标**点击一次，400ms 后恢复可触摸；抖音会真正获得焦点并弹出键盘。两次点击间有 500ms 防抖，避免一次点击触发两次回放。
5. 第二下点发送按钮。坐标仍按真实屏幕宽高归一化存储，运行时乘以真实屏幕尺寸还原。满两个点立即自动保存并关闭校准页，Toast 显示两个归一化坐标。
6. 双击任意空白处可撤销上一个已记录的点；返回键取消且不保存。若无障碍服务未开启，仍会记录坐标，但不会回放点击，并 Toast「请先开启无障碍服务」。

> 只有能确认下方是目标应用时才建议开启校准。校准坐标只在无障碍节点定位失败时兜底；正常情况下优先直填 `isEditable` 节点，其次读取「说点什么 / 和主播聊两句 / 写评论 / 发个评论」文本或点击输入框。

## 7. 使用步骤

1. 依次开启悬浮窗、通知、无障碍三项权限。
2. 先进入抖音直播间，确认评论输入框可见。
3. 首次使用建议先按第 6 节在抖音直播间界面完成一次透明校准；之后回到抖屏助手点「开始」，或者打开悬浮球点「开始」。
4. 再切回抖音；如果不是从抖音内启动，工具会先显示“等待切回抖音”，检测到抖音恢复前台后自动开始。
5. 悬浮面板可观察状态、已发送条数、下一轮倒计时和「上一轮 xxx ms」；也可按「暂停」「停止」「试一轮」「补发一次」「抓节点」。
6. 调试建议先暂停，再点「试一轮」，看“日志”页里每一步结果。
7. **判断是否被禁言**：先暂停（或停止）主循环，再点悬浮窗「补发一次」。它只发一轮、不追加任何后缀、结束后仍保持暂停/停止，不会自动继续；默认内容是 `怎么回事？发不了了`。长按「补发一次」按钮可弹出输入框修改，设置页的「补发内容」也可改，保存后立即生效。
8. 「补发一次」完成后，悬浮窗会醒目显示 5 秒：`已发出`、`未发出：找不到输入框`、`未发出：文字没进去（输入框为空或内容不匹配）` 或 `未发出：发送按钮不可点（大概率被禁言）`；日志页同时追加一条包含原文、各阶段耗时和失败原因的记录。

## 8. 发送节奏与输入链路

- 最小间隔、最大间隔都用数字输入框，范围 **0.0~60.0 秒**，步进 **0.1 秒**；默认 **0.0 ~ 0.0 秒**。0.0 表示两轮之间只经过系统必要的手势派发与无障碍调用，不使用最小延迟兜底；下一轮用 `later(0)` 调度。
- 输入框下方实时预览实际区间，例如「实际间隔 0.0 ~ 0.0 秒（抖动已关闭）」。
- 「启用发送抖动」默认**关闭**。关闭时，实际间隔严格等于区间内的随机值，不再额外叠加任何延迟。
- 打开后显示抖动上限输入框（0.1~60.0 秒，默认 0.5 秒）。实际间隔 = 区间随机值 + 0~抖动上限的随机值。
- 最小值大于最大值或数值越界时，会自动纠正并 Toast 提示；所有参数改动下一轮即时生效，无需重启服务。
- 每轮开始先尝试直填：在无障碍树中找 `isEditable` 节点，直接 `ACTION_SET_TEXT`；失败才 `ACTION_FOCUS` 后再试一次，然后校验节点 text 是否包含目标内容。直填成功不点击输入框、不弹键盘，直接找发送按钮；任一步失败自动退回旧的点击输入框 → 键盘 → 写入 → 校验路径。
- 自动轮次点击发送后只等本次点击手势完成（系统必要时间），随后立即结束本轮并调度下一轮，不再单独等待 800~1500ms 校验；下一轮能找到输入框/可编辑节点即说明上一轮已发出，找不到才以 20ms 间隔轮询、上限 2000ms，超时判失败。手动「试一轮」和「补发一次」仍保留发送结果校验，以维持禁言判断能力。
- 每轮日志都写入「定位 x ms / 输入 x ms / 发送 x ms / 空闲 x ms / 总计 x ms」并标注路径是「直填」还是「点击输入框」；空闲是这一轮开始前的调度间隔，0.0 间隔时为空闲 0ms。悬浮窗显示「上一轮 xxx ms」。
- 老版本配置可迁移：旧的 3~8 秒默认值会升级为当前默认值；自定义间隔保留。

## 9. 参数说明

| 参数 | 默认 | 说明 |
|---|---:|---|
| 消息列表 | 3 条示例 | 一行一条，空行忽略；修改后下一轮生效 |
| 发送模式 | 随机抽取 | 随机抽取 / 顺序循环 |
| 防重复后缀 | 开启 | 每条评论末尾追加后缀 |
| 后缀类型 | 符号+数字+表情代码 | 可多选 |
| 后缀数量 | 2 个 | 1~3 个 |
| 后缀去重 | 最近 20 条 | 记录已发送的完整后缀并尽量避开 |
| 最小间隔 | 0.0 秒 | 数字输入，0.0~60.0 秒，步进 0.1 |
| 最大间隔 | 0.0 秒 | 数字输入，0.0~60.0 秒，不得小于最小值 |
| 发送抖动 | 关闭 | 开关；关闭时实际间隔严格等于区间随机值，不额外加任何延迟 |
| 抖动上限 | 0.5 秒 | 开关打开后显示，0.1~60.0 秒；实际额外延迟为 0~该上限随机 |
| 输入路径 | 直填优先 | 先 `ACTION_SET_TEXT`，失败聚焦重试；再失败回退点击输入框 |
| 发送后校验 | 自动轮次零等待 | 等本次点击手势完成即结束；下一轮定位兼作校验；手动补发保留结果校验 |
| 点击抖动 | ±3px | 避免永远落在完全相同的像素 |
| 按压时长 | 25~40ms | 每次点击随机 |
| 目标包名 | `com.ss.android.ugc.aweme` | 只操作该包名窗口 |
| 校准坐标 | 未设置 | 输入框 / 发送按钮归一化坐标 |
| 补发内容 | `怎么回事？发不了了` | 「补发一次」的单发文本；不追加后缀，单行，修改后立即生效 |

符号池：`~ ～ … !! ？？ 。。 ☀ 🌙 ✨ 🍀 👍`

抖音表情代码池：`[比心] [爱心] [鼓掌] [玫瑰] [666] [一起加油] [坏笑] [礼物] [黄脸祈祷] [害羞] [微笑]`

示例效果：`主播唱得真好听~[比心][666]123`

> 单一类型且后缀数量为 1 时，组合总数可能不足 20 条，无法绝对满足“最近 20 条不重复”；此时会选择可用的组合并继续轮转。

## 10. 常见问题

**发送键点不动**
- 先校准发送按钮。
- 看日志里是否显示「发送按钮置灰」；置灰说明文字没有真正进入输入框。
- 工具会自动优先直填 `isEditable` 节点；直填被拒会退回点击输入框，随后才使用 `ACTION_SET_TEXT` / 剪贴板 + `ACTION_PASTE` 的旧链路。日志会明确写出本轮路径。

**文字没有进去**
- 确认点击的是直播间评论输入框，而不是其他搜索框。
- 看日志里 `ACTION_SET_TEXT` 是否返回 true、校验文本是否包含目标内容。
- 用「抓节点」检查输入框是否暴露 `editable=true`、节点 text 是否可读。

**被限流 / 发送后看不到**
- 暂停并降低频率，减少重复内容。
- 平台可能有发送频率限制、风控或折叠展示；本工具不包含绕过风控的处理。

**耗电 / 被系统杀后台**
- 保持通知常驻，允许自启动和后台运行。
- ColorOS / MIUI 请在电池设置里把本 App 设为“不限制”。
- 无障碍服务可能被系统在长时间无操作后中断；重新开启即可。

**悬浮窗看不到**
- 检查“显示在其他应用上层”权限。
- 打开 App 点「显示 / 恢复悬浮窗」。
- 若从悬浮面板点过「隐藏」，也可以从通知进入 App 恢复。

**为什么要前台服务**
- 常驻通知提供暂停 / 继续 / 停止入口，并降低进程被系统回收的概率。通知属于低优先级，不响铃。

## 11. 抓节点、日志与分享

- 「抓节点」只抓当前目标包名窗口的 `rootInActiveWindow`，记录 `className / text / contentDescription / viewIdResourceName / boundsInScreen / clickable / editable` 等字段。
- Android 10+ 通过 MediaStore 写入 `Download/dyshuaping_nodes.txt`；Android 9 及以下需要存储权限，未授权时会退回到应用私有目录并弹出分享。
- 运行日志最多保留 200 条，存放在内存中，可在「运行日志」页一键复制或分享。
